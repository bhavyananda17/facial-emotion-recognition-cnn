# Results summary

Test accuracy of this reproduction against the paper (Raj and Demirkol, Scientific Reports 15:38940, 2025). Generated by `scripts/make_summary.py` from `results/*/*/run_info.json`; seed 42; Apple M5 Pro GPU.

| Dataset | Paper reports | **Mine, paper protocol** | **Mine, clean protocol** | Paper minus clean | Macro-F1 (paper / clean) |
|---|---|---|---|---|---|
| CK+ | 95% | **94.4%** | **90.9%** | +3.5 pts | 0.924 / 0.865 |
| RAF-DB | 83% | **83.0%** | **83.2%** | -0.2 pts | 0.748 / 0.746 |
| FER2013 | 64% | **65.3%** | **64.8%** | +0.6 pts | 0.613 / 0.608 |

**Paper protocol** copies the official notebooks: early stopping and learning-rate reduction watch the *test set*. **Clean protocol** changes only that: they watch a stratified 10% slice held out from training, and the test set is used once at the end. Same model, seed, augmentation and training images.

| Dataset | Test images | Clean validation slice | Epochs run (paper / clean) | Training time (paper / clean) |
|---|---|---|---|---|
| CK+ | 198 | 75 | 100 / 56 | 2.2 / 1.2 min |
| RAF-DB | 3,068 | 1,225 | 100 / 100 | 80.9 / 72.7 min |

## Do the numbers reproduce?

Yes. In the paper protocol the three results are within 1.3 points of the reported ones (CK+ -0.6, RAF-DB -0.0, FER2013 +1.3). The paper rounds to whole percentages and reports a single unseeded run, so differences of this size are expected.

## Does using the test set for early stopping inflate the numbers?

Not measurably, on any of the three datasets. The paper-minus-clean gap is -0.2 points on RAF-DB (6 images of 3,068) and +0.6 on FER2013 (41 images of 7,178), with the clean run ahead on RAF-DB.
On CK+ the seed-42 gap is +3.5 points, but over 4 training seeds the means are 94.8 ± 0.5% (paper) and 94.1 ± 2.6% (clean): a gap of +0.8 points, smaller than the seed-to-seed spread (`results/ck/multi_seed.md`).

**Likely reason (a hypothesis, not tested):** the paper's `ReduceLROnPlateau(factor=0.001)` cuts the learning rate a thousand-fold at the first plateau (to 1e-6 around epoch 45), so the model barely changes afterwards. Selecting the best epoch with the test set only helps if epochs differ; here the late epochs are almost identical.

**What this does and does not show.** The protocol is still methodologically unsound (the test set influences training), but on these models and datasets that did not change the reported accuracy by more than the noise. RAF-DB and FER2013 were run with a single seed, so differences under about a point should not be read as a direction.

## Other problems that do matter

- **Mislabelled per-class results in the original.** The notebooks' label lists for FER2013 and RAF-DB do not match Keras' folder order, so the paper's per-class confusion matrices, ROC curves and Table 4 are mislabelled (4 of 7 RAF-DB classes; Sad / Surprise / Neutral on FER2013). Confirmed against the paper's own Table 4 (README).
- **CK+ near-duplicate frames.** 91% of CK+ test images have a sibling frame from the same sequence in training, so CK+ accuracy is optimistic under both protocols.
- **Learning-rate factor 0.001** and an unused ExponentialDecay schedule (README, "Differences from the original code").
